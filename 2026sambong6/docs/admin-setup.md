# 선생님 계정 인증 (admins 허용목록)

학생은 지금처럼 익명 로그인과 PIN으로 들어갑니다. 할인·상점 가격·퀘스트/직업 편집·월드 설정처럼 선생님만 저장하는 항목은 Google 또는 이메일/비밀번호로 로그인한 뒤, Firestore `admins/{uid}` 문서가 있어야 저장됩니다.

`updatedBy`에 `gm`을 넣는 방식으로는 더 이상 통과하지 않습니다.

## 배포 순서

규칙을 앱보다 먼저 게시하면, 아직 인증 버튼이 없는 구 버전에서 할인 저장이 막힙니다. 아래 순서를 지킵니다.

1. Firebase 콘솔에서 로그인 공급자를 켭니다.
2. `admins/{uid}` 문서를 만듭니다.
3. 이 변경이 들어간 앱을 배포합니다 (main 머지 후 GitHub Pages).
4. 마지막에 `firestore.rules`를 게시합니다.

```bash
firebase deploy --only firestore:rules --project sambong-world-2026
```

## 콘솔에서 할 일

1. Firebase 콘솔 → Authentication → Sign-in method 에서 **Google**과 **이메일/비밀번호**를 사용 설정합니다. Settings → Authorized domains 에 `dmlwjd85.github.io`가 있는지 확인합니다.
2. 배포된 앱에서 GM(`gm` 또는 `gm_a`) PIN으로 들어간 뒤 **선생님 계정 인증**을 한 번 누릅니다. 아직 `admins` 문서가 없으면 화면에 **권한 없음**이 나오는 것이 정상입니다. 콘솔 Authentication → Users 에서 사용자를 직접 추가해도 됩니다.
3. Authentication → Users 에서 그 계정의 **사용자 UID**를 복사합니다. 이메일을 문서 ID로 쓰면 안 됩니다. 같은 이메일이라도 Google 계정과 이메일/비밀번호 계정의 UID는 다릅니다.
4. Firestore → 데이터 → 컬렉션 `admins` → 문서 ID = 복사한 UID. 필드 예시는 아래와 같습니다.
   - `role` (string): `gm`
   - `email` (string): 선생님 이메일
   - `classIds` (array): 이 계정이 설정을 고칠 학급 ID. 기존 삼봉 학급은 `sambong-class-2026` 입니다. 학급 ID는 주소의 `?class=` 값, 또는 학급을 만든 뒤 화면에 나오는 ID와 같습니다.
   - `createdAt` (timestamp): 만든 시각
5. 보조 마스터(`gm_a`) 선생님도 같은 방법으로 문서를 하나 더 만듭니다. 그 계정이 맡을 학급 ID를 `classIds`에 넣습니다.
6. 앱을 새로고침해 배지가 **인증됨(이메일)** 인지, 할인 저장이 되는지를 확인합니다.
7. 그 다음 규칙을 게시합니다.

클라이언트는 `admins` 문서를 만들거나 고칠 수 없습니다. 다른 사용자의 `admins` 문서도 읽을 수 없습니다.

## 앱에서 보이는 것

- GM 화면(선생님 설정, 월드 설정, 캐릭터 상점 할인)에 **선생님 계정 인증** 버튼과 배지가 있습니다.
- 배지는 `미인증`, `인증됨(이메일)`, `권한 없음` 중 하나입니다.
- 인증은 Google 팝업이 먼저입니다. 팝업이 막히거나 학교망에서 Google 로그인이 안 되면 이메일/비밀번호 입력으로 넘어갑니다.
- GM이 로그아웃하면 그 브라우저의 선생님 세션을 끊고 익명 로그인으로 되돌립니다. 상단 내비게이션의 **로그아웃** 버튼은 GM이 로그인한 동안 글자로 남아 있습니다.
- 선생님 Google/이메일 로그인은 브라우저 탭 세션에만 남습니다. 탭을 닫으면 사라집니다.
- PIN 로그인 중 학생만 남아 있는 선생님 세션을 끊습니다. `gm` / `gm_a` 로그인(새로고침 자동 로그인 포함)은 그 세션을 유지합니다. 원래 학급(`sambong-class-2026`)의 PIN 자동 로그인은 새로고침 때 그 정리에 같이 끊기지 않습니다. 학생 자동 로그인이 화면에 붙은 뒤에만 선생님 세션을 익명으로 되돌리고, 저장한 PIN은 그대로 둡니다.
- GM 화면을 15분 동안 건드리지 않으면 선생님 인증을 확인 없이 끝냅니다. 원래 학급은 그때 PIN 로그인과 화면을 유지하고 선생님 인증 배지만 미인증으로 내립니다. 로그인 저장소를 지우거나 새로고침하지 않습니다. 다른 학급은 로그인 저장소를 지우고 익명 세션으로 되돌린 뒤 새로고침합니다. 마우스 이동, 휠, 스크롤도 5초 간격으로 활동으로 셉니다. 수업도구를 전체 화면으로 띄우거나 학생 화면에 공유 중이면 이 자동 로그아웃을 하지 않습니다.
- 수업 종료 자동 XP는 학생 문서의 `lastClassXpSlot`으로 이미 지급했는지 판단합니다. 키는 한국 표준시 종 시각 `YYYY_MM_DD_HH:MM`입니다. 규칙은 오늘 평일에 이미 지난 종 가운데 가장 최근 시각에, 경험치가 정확히 +5일 때만 이 필드를 바꿉니다. 그 1분을 놓쳐도 다음 종 전까지 그 시각만 다시 지급할 수 있습니다. 더 이전 종은 다시 받지 못하고, 주말과 09:40 이전에는 기록이 거부됩니다. 학생마다 트랜잭션을 나눠, 경험치가 숫자가 아닌 학생은 건너뛰고 화면에 학번을 알립니다. 한 명의 실패가 반 전체를 막지 않습니다. 학생 화면의 저장은 `lastClassXpSlot`을 보내지 않아 서버 값을 유지합니다. `settings/autoXp`는 공지용이라, 학생이 그 문서를 먼저 써도 경험치 지급을 건너뛰지 않습니다. 슬롯 시각은 기기 시간대가 아니라 한국 표준시로 계산합니다. 기기 시계나 시간대가 달라 기록이 거절되면 화면에 안내를 띄웁니다. Cloud Functions는 넣지 않았습니다. 공개 와일드카드가 학생 문서의 봉·경험치 상한과 삭제를 아직 덮습니다. 그 구멍은 이번 변경에서 닫지 않았습니다.
- 1회 마이그레이션(방패 재고 표식, 시즌 2 무기/드래곤볼 정리, 시즌 1 환불 표식)은 선생님 인증이 있는 동안에만 기록합니다.

규칙을 게시한 뒤에는 새 학급을 만들거나 개설 요청을 허락할 때도 선생님 인증이 필요합니다. 만드는 계정은 `classIds`에 `sambong-class-2026`이 있어야 합니다. 앱이 새 학급 ID로 `approvedClassIds/{학급ID}` 표식을 만든 뒤 `settings/global`을 만듭니다. 표식의 `createdBy`는 그 요청을 실행한 선생님 uid입니다. 다른 선생님은 그 표식만으로 설정을 만들지 못합니다. 만든 직후 그 ID를 `classIds`에 넣어야 이후 할인·공지·은행 설정 수정이 됩니다.

## 학급 범위

`settings/global` 경로는 `artifacts/{학급ID}/public/data/settings/global` 이라 학급마다 문서가 다릅니다. `admins/{uid}` 는 전역 문서입니다.

- 이미 있는 학급의 GM 전용 키를 고치려면 `classIds` 배열에 그 학급 ID가 있어야 합니다. 다른 학급 문서는 같은 선생님 계정으로도 수정할 수 없습니다.
- `classIds` 가 없거나 비어 있으면 수정이 거부됩니다.
- 새 `settings/global` 생성은 `classIds`에 그 학급 ID가 있거나, 시드 학급(`sambong-class-2026`) 선생님이 만든 `approvedClassIds/{학급ID}` 문서의 `createdBy`가 지금 로그인한 uid와 같을 때만 됩니다. 개설 요청 문서 ID는 임의 문자열이라 규칙이 그 컬렉션을 조회하지 못하고, 같은 단계에 만드는 표식 문서를 봅니다. 익명 사용자는 빈 설정 문서도 만들 수 없습니다. 학급 개설 요청을 보낸 학생의 Firebase uid는 표식에 없습니다. 표식에 묶이는 계정은 학급 만들기를 실행한 시드 학급 선생님입니다.

## 테스트

- `npm test` 는 단위 테스트만 돌립니다. Java가 없어도 됩니다. 규칙 테스트는 에뮬레이터가 없으면 건너뜁니다.
- `npm run test:rules` 는 Firestore 에뮬레이터로 규칙을 검사합니다. Java가 필요합니다.

## 아직 잠그지 않은 settings/global 키

학생이거나, 로그인만 된 아무 클라이언트이거나, 이번에도 학생 기능이 같이 쓰는 키입니다.

| 키 | 잠그지 않은 이유 |
| --- | --- |
| `lotto` | 학생이 로또를 사고, 추첨도 클라이언트에서 기록합니다. |
| `musicTimeQueue` | 학생이 신청곡을 올립니다. |
| `shieldStock` | 학생이 방패를 살 때 재고를 줄입니다. `shieldStockFixedTo5At` 표식만 GM 전용입니다. |
| `thoughtBoard` | 학생이 생각게시판에 글을 올립니다. |
| `schoolWeather` | 열려 있는 화면이 날씨를 갱신해 저장합니다. |
| `marketQuotes` | 열려 있는 화면이 시세를 갱신해 저장합니다. |
| `worldCupBet` | 마감 시각이 되면 아무 클라이언트가 베팅 문서를 닫습니다. 학생 베팅금은 학생 문서에 있습니다. |
| `lastSalaryWeek` | 금요일 주급 정산을 아무 로그인 클라이언트가 실행합니다. |
| `lastAutoXpTime` | `settings/global`에서는 뺐습니다. 지급 여부는 학생 문서 `lastClassXpSlot`이고, `settings/autoXp`는 공지용입니다. |

학습 온도계의 학생별 값은 `settings/learningThermometer/votes/{학생ID}` 문서의 `value` 하나입니다. 부모 문서의 `min`~`max` 안 정수만 허용합니다. 부모 문서를 만드는 것도 그 학급 선생님만 가능합니다. Firebase 로그인 uid는 학번이 아니라서, 학번 문서는 그 학급이 `classIds`에 있는 선생님만 쓸 수 있습니다. 학생은 문서 ID가 자기 uid이고 24자 이하일 때만 값을 쓸 수 있고, 정산은 학번 목록만 읽습니다. `settlementStatus`, `settlementKey`를 비롯한 정산 필드와 `min`/`max` 변경은 선생님만 가능합니다. PIN만 로그인한 GM 화면은 슬라이더와 +/- 버튼을 `disabled`로 두고 포인터·포커스를 끊습니다. **선생님 인증 필요** 배지를 보입니다. 저장되지 않은 값은 **미저장**으로 표시합니다. 15:00 자동 정산은 선생님 인증이 있을 때만 실행되고, 없을 때는 안내 후 건너뜁니다. **지금 XP 반영** 버튼은 GM 화면에 남아 있으며, 인증이 없으면 인증을 요구합니다. `settings/global`의 옛 `learningThermometer` 필드는 GM 전용입니다. 정산으로 오르는 경험치는 학생 문서 규칙(한 번에 +650 이하)에 다시 걸립니다.

## 막혔을 때

| 증상 | 복구 |
| --- | --- |
| 다른 학급 설정이 거부됨 | `admins/{uid}.classIds`에 그 학급 ID 문자열이 있는지 확인합니다. 학급을 방금 만들었다면 화면에 나온 ID를 배열에 추가합니다. |
| 다른 Google 계정으로 로그인함 | 실제로 로그인한 계정의 UID로 `admins` 문서를 추가합니다. |
| 비밀번호를 잊음 | 콘솔에서 비밀번호 재설정 메일을 보내거나, 새 계정의 UID를 `admins`에 추가합니다. |
| Google 팝업이 막힘 | 앱의 이메일/비밀번호 로그인을 사용합니다. |
| 규칙을 잘못 게시함 | Firestore 규칙 탭의 **이전 버전**에서 바로 되돌립니다. |
| 학생 기능이 막힘 | `GM_ONLY` 목록에 학생도 쓰는 키가 들어간 것입니다. 그 키를 빼고 규칙만 다시 게시합니다. 앱을 다시 배포하지 않아도 됩니다. |
| 콘솔로 당장 값을 고쳐야 함 | `isAdmin()`은 그대로 두고 Firestore 콘솔에서 `settings/global`을 직접 수정합니다. 콘솔은 규칙을 우회합니다. |

콘솔 소유자(Google Cloud 프로젝트 소유자)를 잃는 경우만 영구히 잠깁니다. 소유자는 두 명 등록하는 것을 권합니다.
