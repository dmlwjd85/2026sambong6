# 마스터 PIN으로 저장하기

학생은 지금처럼 익명 로그인과 PIN으로 들어갑니다. 마스터(`gm`, `gm_a`)도 PIN으로 들어온 익명 세션 그대로 할인·상점·퀘스트·월드 설정·학습 온도계를 저장합니다. Google 로그인이나 `admins/{uid}` 문서는 저장 조건이 아닙니다.

`updatedBy`에 `gm`을 넣는 방식으로 권한을 나누지는 않습니다. 규칙은 로그인한 세션인지와 값 형식만 봅니다.

## 배포할 규칙 파일

앱 루트 `2026sambong6/firestore.rules` 입니다.

이 문서는 동작 설명입니다. 규칙을 원격에 올리는 작업은 포함하지 않습니다.

## 아직 검사하는 형식

- 할인 `shopDiscount`: 켜짐 여부, 0~100 정수, 켜져 있으면 시작·종료 시각
- 수업 XP 공지 `settings/autoXp`와 학생 문서 `lastClassXpSlot`
- 학습 온도계 부모 문서와 표의 `value` 범위
- 학급 승인 표식 `approvedClassIds`: `classId`, `status == approved`, `createdBy`가 지금 세션 uid
- `settings/global` 삭제 금지, 학생 문서 삭제 금지
- 학생 경험치·봉의 한 번에 올릴 수 있는 폭

선생님 화면이 주로 쓰는 키 이름 목록(`gmOnlyKeys`)은 규칙 파일에 남아 있습니다. 그 키를 선생님만 쓰게 막지는 않습니다.

## 학생 로그인

학생 자동 로그인은 익명 세션으로 학생 문서를 읽고 씁니다. `gm` / `gm_a`가 아닌 PIN 로그인은, 브라우저에 남아 있는 Google·이메일 세션이 있으면 학생 문서를 읽기 전에 그 세션을 끊습니다. 끊기에 실패하면 저장된 PIN은 그대로 두고 로그인을 멈춥니다.

## 보안

PIN 대조는 브라우저에서만 합니다. Firestore 규칙은 마스터와 학생을 구분하지 못합니다. 개발자 도구로 로그인한 누구든, 학생 포함, 형식이 맞는 선생님 설정을 쓸 수 있습니다.

더 안전하게 가려면, 규칙에 다시 선생님 계정을 두는 쪽이 좋습니다. 예시는 Firebase 이메일/비밀번호 계정 하나를 만들고 비밀번호를 지금 마스터 PIN과 같게 두는 방법입니다. 이 저장소는 그 계정을 만들지 않았고, 규칙도 그 계정을 요구하지 않습니다.

## 막혔을 때

| 증상 | 복구 |
| --- | --- |
| 저장이 형식 오류로 거부됨 | 할인 퍼센트, 온도계 범위, 수업 XP 시각처럼 규칙이 보는 값을 확인합니다. |
| 규칙을 잘못 게시함 | 백업 규칙을 Firebase 콘솔에 붙여 넣거나, 백업 파일로 `firebase deploy --only firestore:rules` 를 실행합니다. |
| 학생 기능이 막힘 | 학생 문서의 경험치·봉 한도나 수업 XP 슬롯 형식을 확인합니다. 앱을 다시 배포하지 않아도 규칙만 되돌릴 수 있습니다. |

## 테스트

- `npm test` 는 단위 테스트만 돌립니다. Java가 없어도 됩니다. 규칙 테스트는 에뮬레이터가 없으면 건너뜁니다.
- `npm run test:rules` 는 Firestore 에뮬레이터로 규칙을 검사합니다. Java가 필요합니다.
