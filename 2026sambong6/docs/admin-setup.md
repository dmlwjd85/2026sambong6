# 마스터 PIN으로 저장하기

학생은 지금처럼 익명 로그인과 PIN으로 들어갑니다. 마스터(`gm`, `gm_a`)도 PIN만 입력합니다. Google 로그인이나 `admins/{uid}` 문서는 저장 조건이 아닙니다.

PIN은 교사가 직접 저장할 때만 묻습니다. 화면을 열 때는 묻지 않습니다. 맞는 PIN이면 `gmSessions/{uid}`가 10분 동안 생기고, 저장할 때마다 10분이 연장됩니다. 할인, 상점, 공지, 학급 승인, 온도계 값을 손으로 바꾸는 저장은 그 세션이 살아 있을 때만 됩니다.

수업 경험치 자동 정산, 주급, 온도계 자동 정산은 GM/TV 탭에서 세션 없이 그대로 돕니다.

## 배포할 규칙 파일

앱 루트 `2026sambong6/firestore.rules` 입니다.

이 문서는 동작 설명입니다. 규칙을 원격에 올리는 작업은 포함하지 않습니다.

## PIN을 서버로 옮기는 순서

1. Firebase 콘솔 → Firestore → `secrets` 컬렉션에 학급 ID와 같은 문서 ID로 문서를 만듭니다. 예: `secrets/sambong-class-2026`. 필드는 `pin` 하나이고, 값은 반드시 문자열입니다. 숫자 타입으로 저장하면 로그인이 거절됩니다.
2. 다른 학급이 있으면 학급마다 `secrets/{학급ID}`를 같은 방식으로 만듭니다.
3. `2026sambong6/firestore.rules`를 배포합니다.
4. 이 커밋의 앱을 배포하고 선생님 화면을 새로고침합니다. 저장할 때 PIN을 한 번 넣으면 세션이 생기고, 앱이 `students/student_gm`과 `students/student_gm_a`의 `pin` 필드를 지웁니다.
5. 운영 마스터 PIN을 바꿉니다. 예전 PIN은 공개 학생 문서에 있었습니다. secrets에 같은 값을 넣은 뒤, 앱에서 세션을 열고 PIN을 새 값으로 바꾸거나 콘솔에서 `secrets/{학급ID}.pin` 문자열을 새 번호로 고칩니다.
6. 콘솔에 학생 문서 `pin`이 남아 있으면 그 필드만 지웁니다. 학생 문서의 PIN은 지우지 않습니다.

공개 `pin`을 앱보다 먼저 지우면, 예전 앱은 마스터로 들어오지 못합니다. secrets 문서를 먼저 만들고, 규칙과 앱을 이어서 배포한 뒤에 공개 `pin`을 지웁니다.

## 세션에 PIN을 넣지 않는 이유

Firestore는 `request.resource.data`를 그대로 저장합니다. PIN을 보내 비교만 하고 저장하지 않는 쓰기는 한 문서로는 되지 않습니다. 같은 문서를 한 배치나 한 트랜잭션에서 두 번 쓰지도 못합니다. 그래서 다음 구조를 씁니다.

- `secrets/{학급ID}`에만 PIN이 있습니다. 읽기와 삭제는 거부합니다. 시드 학급 문서는 콘솔에서만 만듭니다.
- `gmPinProofs/{uid}`는 PIN이 맞을 때만 잠시 생깁니다. 읽기는 거부하고, 세션을 만든 뒤 앱이 지웁니다.
- `gmSessions/{uid}`는 `classId`와 `expiresAt`만 가집니다. `pin` 키가 있으면 규칙이 거절합니다. 본인만 읽을 수 있고, 만료는 지금부터 10분 이내만 쓸 수 있습니다. 살아 있는 세션만 증명 없이 연장됩니다. 만료된 뒤에는 새 증명이 필요합니다.

4자리 PIN의 해시를 세션에 남기면, 데이터베이스가 새는 순간 바로 복원됩니다. 세션에는 PIN도 해시도 없습니다. 증명 문서를 지우기 전에 장애가 나면 PIN이 그 문서에 잠시 남지만, 클라이언트는 읽지 못합니다.

## 아직 검사하는 형식

- 할인 `shopDiscount`: 켜짐 여부, 0~100 정수, 켜져 있으면 시작·종료 시각. 유효한 세션만 바꿉니다.
- 수업 XP 공지 `settings/autoXp`와 학생 문서 `lastClassXpSlot`. 종 시각 형식과 중복 간격은 그대로이고, 세션 없이도 그 형식이면 씁니다. 삭제는 금지입니다.
- 학습 온도계. 값을 손으로 바꾸는 저장은 세션이 필요합니다. 자동 정산은 잠금을 잡고, 표를 0으로 되돌리고, running에서만 오늘 이전 키로 완료할 수 있습니다. 완료 위조와 -20 같은 다른 학생 표는 세션 없이 거절됩니다.
- 학급 승인 표식 `approvedClassIds`: 시드 학급 세션만, `createdBy`가 지금 uid일 때만
- `settings/global` 삭제 금지, 학생 문서 삭제 금지, `admins` 쓰기 금지
- 학생 경험치·봉의 한 번에 올릴 수 있는 폭
- 마스터 학생 문서(`student_gm`, `student_gm_a`)에는 `pin` 필드를 다시 넣지 못합니다.

로또처럼 학생이 쓰는 키는 세션 없이 그대로 저장됩니다.

## 학생 로그인

학생 자동 로그인은 익명 세션으로 학생 문서를 읽고 씁니다. 학생 PIN은 학생 문서에 남아 있습니다. 마스터 PIN은 읽지 않습니다.

`gm` / `gm_a`가 아닌 PIN 로그인은, 브라우저에 남아 있는 Google·이메일 세션이 있으면 학생 문서를 읽기 전에 그 세션을 끊고, 같은 uid의 마스터 세션 문서도 지웁니다. 끊기에 실패하면 저장된 PIN은 그대로 두고 로그인을 멈춥니다.

## PIN 대입

규칙이 막는 것:

- 학급마다 `gmPinAttempts/{학급ID}` 하나입니다. 틀린 PIN도 증명과 같은 배치에서 횟수를 정확히 1 올립니다. 규칙은 `getAfter`와 `existsAfter`로 그 증가를 확인합니다. 횟수를 그대로 두고 증명만 쓰는 것은 거절됩니다.
- 10번째에 `lockedUntil`을 15분 뒤로 씁니다. 잠긴 동안에는 맞는 PIN도, 다른 uid도 세션을 만들지 못합니다. 맞는 PIN으로 횟수를 0으로 되돌리는 것은 잠기기 전(1~9번째)만 됩니다.
- 로그인 칸은 4자리에서 12자리까지 받습니다. 이미 쓰던 4자리 PIN은 그대로 동작합니다. 새 학급을 앱에서 만들 때의 초기 PIN은 6자리입니다.

한계:

- 잠금 문서를 트랜잭션 없이 동시에 쓰면, 두 요청이 같은 횟수를 보고 둘 다 통과할 수 있습니다. 앱은 트랜잭션으로 올립니다. 규칙은 그 동시 쓰기를 완전히 막지는 못합니다.
- 10번째 기록과 함께 잠금이 걸립니다. 그 10번째 PIN이 맞아도 세션은 열리지 않고, 15분이 지나야 다시 입력합니다.
- App Check는 이 저장소에 사이트 키가 없어 켜지 않았습니다. 켜면 앱이 막힐 수 있어, 콘솔에서 앱을 등록한 뒤에 따로 검토하는 편이 안전합니다.
- 예전에 공개됐던 4자리 PIN은 배포 뒤 새 번호로 바꾸는 것이 좋습니다.

## 막혔을 때

| 증상 | 복구 |
| --- | --- |
| 저장이 형식 오류로 거부됨 | 할인 퍼센트, 온도계 범위, 수업 XP 시각처럼 규칙이 보는 값을 확인합니다. |
| PIN이 맞는데 마스터로 들어가지 못함 | `secrets/{학급ID}.pin`이 문자열인지, 앱에 남은 공개 `pin`과 같은지 확인합니다. |
| 15분 동안 PIN이 거절됨 | 그 학급의 시도가 10번이 된 것입니다. uid를 바꿔도 풀리지 않습니다. 15분 뒤에 다시 입력합니다. |
| 규칙을 잘못 게시함 | 백업 규칙을 Firebase 콘솔에 붙여 넣거나, 백업 파일로 `firebase deploy --only firestore:rules` 를 실행합니다. |
| 학생 기능이 막힘 | 학생 문서의 경험치·봉 한도나 수업 XP 슬롯 형식을 확인합니다. 앱을 다시 배포하지 않아도 규칙만 되돌릴 수 있습니다. |
